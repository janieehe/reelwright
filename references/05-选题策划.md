# 工序 5 · 选题策划

## 定位

把内容矩阵的内容支柱落地为一份可直接开拍的选题清单，产出保存为 `选题清单.md`，供「脚本撰写」工序随后加载。

## 目标

生成默认 10-20 个选题（每个含标题、内容支柱、形式、平台、预期效果、难度），支持筛选、排除、追加与改单条。

## 上游

读 `内容矩阵.md`（内容矩阵）。选题须归属到矩阵的某个内容支柱，整份清单覆盖多个支柱，避免同质。也可引用 `商家档案.md`、`账号定位.md` 的背景（主营品类、所在城市、客群）让选题更贴合。内容矩阵缺失时：说明「建议先完成『内容矩阵』，选题更有针对性」，随后按用户口述方向直接开始，不阻断。

## 开场白（按场景选）

- **首次创建**：说明用途，确认关键点后开始生成选题
- **修改模式（已有清单）**：展示清单现状，询问要筛选、追加还是调整
- **从其他工序切来**：衔接已聊内容与已加载档案，直接续做

## 生成选题

- 默认 10-20 个；用户指定数量时按指定执行；可先出一批（10 个），用户反馈后再补充
- 每个选题含：标题、内容支柱、形式、平台、预期效果、难度、状态
- 标题具体可执行，一看便知拍什么；贴合商家实际（主营品类、城市、客群），不用行业黑话
- 只使用用户提供或档案中已有的素材与信息，不编造商家不存在的产品、活动、数据

### 字段取值

| 字段 | 取值 |
|------|------|
| 形式 | 口播、探店、教程、Vlog、剧情、图文等 |
| 平台 | 抖音、小红书、视频号（可多选） |
| 预期效果 | 涨粉、种草、转化、互动、信任（只写方向，不给数字承诺） |
| 难度 | 低 / 中 / 高 |
| 状态 | 待拍 / 已排除 |

## 展示与交互

- 清单以人话呈现：分组列表或表格，列名用中文（编号、标题、内容支柱、形式、平台、预期效果、难度、状态）
- 不给用户看任何机器可读内容（key、frontmatter、路径）
- 覆盖或删除已有条目须先获用户确认；追加与新增直接保存
- 交互四种方式：
  - **筛选 / 排除**：相关选题状态改为「已排除」，或按用户口径保留
  - **追加**：新增选题，不改动已有条目
  - **改单条**：就地修改该条字段，其余不动
  - 每次调整后反馈清单规模：共 N 个、待拍 M 个、已排除 K 个

## 完成标准

用户收尾时完成，标志是用户认可清单（「可以」「就这些」）或提出导出、切到「脚本撰写」。达成时输出：

> 选题清单已建立 ✓（共 N 个，待拍 M 个）。已保存为 `选题清单.md`，可直接切到「脚本撰写」为某个选题写脚本。

用户收尾前持续响应调整请求，不自行宣告完成。

## 边界

- 用户提出脚本、分镜、拍摄方案等诉求时，提示可用对应工序完成
- 营销表述避免绝对化用语
- 预期效果只写方向，不给数字承诺
