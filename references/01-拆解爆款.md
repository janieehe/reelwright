# 工序 1 · 拆解爆款

## 定位

把用户对标的视频或评论区文案，拆成能直接套到自家生意上的脚本结构、分镜结构、选题方向，产出保存为 `爆款拆解.md`，喂给「选题策划」「脚本撰写」「分镜设计」。它是整条线的第一步：先拆透对标，再动手做自己的。

## 关键前提 · 证据边界

灵小兔看不了视频本体，只能靠文字和图片。先定证据等级，再决定能拆多深，结论写实不吹：

| 证据等级 | 拿到了什么 | 能拆什么 | 写法 |
|---------|-----------|---------|------|
| 本地视频（已抽帧+转写） | 跑过 `scripts/video_to_frames_transcript.sh`，有帧图 + 字幕 | 画面层 + 台词层，最全 | 可写「根据画面……」 |
| 画面截图 | 用户贴的关键帧截图 | 景别/构图/光线/服装/道具（静态画面） | 可写「根据截图……」 |
| 口播稿/字幕 | 只有台词与标题 | 脚本结构、叙事、节奏、选题内核 | 运镜/连续动作等画面层写「未知」 |
| 描述 | 用户口述「讲了啥」 | 选题内核、大致结构 | 标「据用户描述」，细节写「未知」 |

- 链接不能自动解析（抖音/小红书/视频号有登录墙与反爬，也拿不到视频本体），只当「来源记录」贴在档案里。
- 只有口播稿或描述时，不得声称「看过画面」。
- 未知内容写「未知」，不凭经验补造参考片里不存在的镜头、动作、数据。

## 第一步 · 判断对象

用户进来先判断要拆什么，选一条主对象（一次先做一条，不混在一起）：

| 对象 | 用户想要 | 喂什么料 | 拆出什么 | 喂给 |
|------|---------|---------|---------|------|
| 一条视频 | 这条为什么爆 | 口播稿/字幕全文 + 标题 + 数据；本地视频则先跑脚本 | 脚本结构 + 分镜结构 + 选题内核 | 07 脚本 / 08 分镜 |
| 文案/评论区 | 用户到底想要啥 | 高赞评论、热评、用户提问原文 | 真实痛点 → 选题方向 | 06 选题 |

## 第二步 · 判断目的，选工作模式（主要针对拆视频）

| 模式 | 用户想要 | 怎么做 |
|------|---------|--------|
| 只拆解 | 搞清楚「这条为什么爆」 | 产出结构拆解，不套用 |
| 拆了套用 | 拆完直接拿去拍 | 产出「可复用脚本模板 + 分镜模板」 |
| 换皮 | 拍法不变，换成我的店 | 锁定脚本结构/镜头结构/节奏卡点，只换人物、服装、场景、产品、店名 |
| 借结构 | 只要爆款的骨架，内容重做 | 只保留叙事结构/选题内核，镜头动作重新设计 |

默认规则：说「拆这条」→ 只拆解；「照这个做一条我的」→ 拆了套用；「拍法不变只换人/场景/产品」→ 换皮（旅拍店、妆造店最常用）；「借它的结构」→ 借结构。拆评论区文案通常对应「只拆解」，不套用「换皮」。

## 信息获取与喂料（两种对象）

视频有「本地文件」，可走工具解析；评论区文案是平台页面上的「文字」，没有本地文件可解析、链接又进不去，所以靠用户**贴文字 + 贴截图**喂进来——灵小兔能读截图也能读文字，拿到后结构化分析。

| 对象 | 获取方式 | 请用户给什么 |
|------|---------|-------------|
| 一条视频 | 工具解析 / 贴料 | 本地视频跑 `scripts/video_to_frames_transcript.sh`；没有就贴口播稿全文 + 关键帧截图 |
| 文案/评论区 | 贴文字 / 截图 | 高赞评论、热评、用户提问的原文（复制粘贴，或截图评论区） |

- 用户往往只丢一个链接或一句「帮我拆这条」。先不急着拆，按对象要「料」，一步步带。
- **截图怎么给**：直接拖进对话，或存到工作目录再报路径（如 `对标素材/评论截图.png`）。文字直接复制粘贴。
- **链接只做来源记录**：抖音/小红书/视频号链接不自动解析，内容得靠贴文字/截图或本地视频转写。
- **评论区文案的证据等级**：截图（能看清高赞数和原文）> 纯文字 > 口述。等级越低，能拆的越粗、越要标「据用户描述」。
- **拿多少拆多少**：缺料不卡住，贴不全就先拆能拆的，缺的标进 gaps，不编造。
- 喂料提问遵守 `00-全局规范.md` 的「提问颗粒度阶梯」：给示例、给选项，答不上就降一档。

## 首次用本地视频 · 引导装工具

用户想拆本地视频但没装过工具时，按下面步骤一步步带（一次只做一步，不一次倒完）：

1. 先让用户跑自检：`bash scripts/video_to_frames_transcript.sh --check`，看缺什么。
2. 缺什么装什么：
   - 缺 ffmpeg → `brew install ffmpeg`
   - 缺 whisper → Apple Silicon 用 `brew install mlx-whisper`；Intel/其他用 `pip install -U openai-whisper`
3. 装完再跑一次 `--check`，全绿才继续。
4. 让用户跑 `bash scripts/video_to_frames_transcript.sh <视频文件>`，把产出的 `<视频名>.analysis/` 路径发回来。
5. 灵小兔读 `meta.txt`、`frames/` 里的截图、`transcript.srt/.txt`，再开始拆。

注意：装工具是用户在自己电脑上执行，灵小兔只给命令、不代跑；装不上就退回「贴口播稿/截图」的老路，不卡住。

## 拆解方法

### 拆一条视频 · 结构五段 + 镜头层

按「结构五段」拆叙事：
1. **钩子**：前 1-3 秒抓了什么（疑问、反常识、场景代入、高能画面）
2. **节奏**：几秒一个信息点、快慢变化
3. **转折**：情绪或信息在哪反转
4. **落版**：怎么收尾、怎么引导
5. **选题内核**：一句话说清它在解决什么/满足什么

再拆「镜头层」：分段原则是出现切镜、机位/景别/运镜变化、主体动作变化、明显转场时新建一段；长镜头按动作阶段分但标记为同一镜头。每段按需提取（拿不到的写「未知」）：

| 维度 | 拆什么 |
|------|--------|
| 时间 | 起止秒数、时长 |
| 镜头 | 景别、角度、机位、运镜、构图、主体位置 |
| 动作 | 主体在做什么、方向、节奏 |
| 场景视觉 | 场景、光线、色彩、服装、道具 |
| 转场字幕声音 | 硬切/转场、字幕内容与时机、音乐卡点/音效 |
| 叙事功能 | 这段在干嘛：钩子/铺垫/证明/情绪/落版 |

拆完给一张「Markdown 镜头表」（给人看）+ 一段结构总结（只讲影响复刻的要点，不重复逐格）。

### 拆文案/评论区 · 痛点聚类

把高赞评论聚类成「真实痛点」，每条痛点转成一句可写的选题方向。

## 分层保留策略（拆视频用）

每个可控层单独定去留：**保留**（原样不动）、**沿用**（保留骨架和节奏，细节按新素材重做）、**替换**（换成用户自己的内容）、**删减**（直接去掉）。

可控层：时间轴、镜头结构、运镜、动作、转场、字幕时机、声音卡点、视觉（人物/服装/场景/产品/店名）、叙事。

两个常用预设：
- **换皮**：时间轴、镜头结构、运镜、转场、声音卡点「保留」；视觉（人物/服装/场景/产品/店名）「替换」；叙事「保留」。
- **借结构**：叙事「保留」或「沿用」；时间轴「沿用」；其余「替换」。

注意：「保持运镜」不等于「保持动作」，两者分开记；「字幕时机」可保留、「字幕文字」可替换。

## 落盘与展示

- 产出写进 `爆款拆解.md`，YAML frontmatter：`type: 爆款拆解` / `updated_at` / `source: 拆解爆款` / `completeness` / `gaps` / `suggestion`
- 拆解结论落到「可复用脚本模板 / 分镜模板 / 选题方向」，不落到 AI 视频提示词——reelwright 面向实拍短视频
- 对话里只展示人话正文，不展示 key、frontmatter、路径
- 对「为什么爆」的归因属推断时标「大概率」，不写成事实
- 不搬运对方原台词当成品，只拆结构、给模板，台词让用户用自己的话写

## 合规

- 版权：不直接复制对方完整文案当用户成品，只提炼结构、模板，台词让用户用自己的话写
- 不夸大数据：用户没贴数据就按「看起来」定性，不编数字
- 不给涨粉/流量承诺，结论落到「可验证的动作」

## 工序衔接

- 拆完收尾提示：可用「脚本撰写」按可复用脚本模板写脚本，或「分镜设计」套分镜模板，或「选题策划」把拆出的方向落成清单
- 拆出的 `爆款拆解.md` 是上游，供 06 选题、07 脚本、08 分镜引用

## 完成标准

拆解报告写清了证据等级、拆出了对应对象的可复用结构、未掌握的信息在 gaps 标注、无版权搬运，且用户认可时输出「拆解已完成 ✓」。
