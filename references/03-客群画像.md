# 工序 3 · 客群画像

## 定位

基于商家档案，通过对话把「我的客户是谁」沉淀成一份 Markdown 画像 `客群画像.md`。让商家看清核心客群与潜在客群是谁、有什么特征、为什么选自己、爱看什么内容、习惯从哪里获取信息。

## 目标

产出一份「核心客群 / 潜在客群」分层的画像，服务后续账号定位与内容矩阵。

## 上游

读 `商家档案.md`（商家档案）。主营品类与客单价决定客群分层与消费偏好的推断方向；不重复采集其中已有信息。档案缺失时：说明「建议先完成『商家档案』，客群分析会更贴合你的生意」，随后按用户口述直接开始，不阻断。

## 开场白（按场景选）

- **首次创建（有商家档案）**：引用档案要点开场，引导描述客户
- **首次创建（无商家档案）**：提示可先建档但不阻断，引导先介绍生意与客户
- **修改模式（已有画像）**：展示当前画像要点，询问调整哪部分
- **从其他工序切来**：衔接已聊内容与已加载档案，直接续做，不重复采集

## 画像方式

- 对话节奏由你判断，一条消息可覆盖多个维度，也可单点深入
- 参考维度按需取舍：客群分层（核心/潜在）、年龄段、性别比、消费偏好、决策动机、内容偏好、触媒习惯；可扩展人群标签、地域来源、决策/影响人关系等
- 用户已提供的信息直接采用并写入，只追问缺口维度
- 基于商家档案与旅拍行业常见规律补充行业洞察（如「婚纱旅拍核心决策人往往是新娘，影响人是闺蜜与伴娘」），标注为「行业常见规律」，不作该商家的确定性事实，不写入档案字段
- 某维度说不清楚或不适用时，标记为空并继续

## 画像表述

- 文件 = YAML frontmatter + Markdown 正文（两级可视化结构）：标题 `# 客群画像` + 生成时间行 + 若干 `## 分层分组`（核心客群 / 潜在客群）+ `- 中文名：值` 键值行
- frontmatter 字段：type / updated_at / source / completeness / gaps / suggestion
- 只含用户已确认的信息；值为空时保留「中文名：」不省略，便于后续补齐
- 分层归类（核心/潜在、人群标签）先按你的理解归纳，请用户确认一次后写入
- 修改时以现有档案为底稿做增量更新

### 字段清单

**核心客群**：人群标签、年龄段、性别比、消费偏好、决策动机、内容偏好、触媒习惯

**潜在客群**：同核心客群对应字段；用户只提到一类客群且确认无潜在客群时，潜在客群分组整组省略。

### 档案模板

```markdown
---
type: 客群画像
updated_at: 2026-09-14 14:10
source: 客群画像
completeness: 完整
gaps: []
suggestion: 建议继续用「账号定位」把核心客群转化为各平台的账号定位
---

# 客群画像

> 生成时间：2026-09-14 · 由 reelwright「客群画像」工序生成

## 核心客群

- 人群标签：备婚情侣、蜜月旅拍客
- 年龄段：22-30 岁
- 性别比：女性约 70%（多为决策发起人）、男性约 30%
- 消费偏好：愿为出片效果与仪式感买单，看重精修张数与妆造增值项
- 决策动机：一生一次的纪念意义 + 社交晒图需求
- 内容偏好：客片案例、旅拍攻略、幕后花絮
- 触媒习惯：小红书搜攻略、抖音刷客片、朋友口碑推荐

## 潜在客群

- 人群标签：亲子旅拍家庭
- 年龄段：30-40 岁（家长）
- 性别比：以妈妈为决策人
- 消费偏好：看重省心与安全，倾向家庭套系
- 决策动机：记录孩子成长 + 亲子出游留念
- 内容偏好：亲子客片、亲子目的地攻略
- 触媒习惯：妈妈群与亲子博主推荐
```

## 完成标准

满足任一条件即收尾：

- 画像覆盖核心客群（人群标签 + 至少 3 个特征维度），潜在客群已识别或已确认不存在，并向用户展示
- 用户表示信息已够用

核心信息齐备时输出「客群画像已建立 ✓」，附一句画像包含什么、后续哪些工序会用到。

## 边界

- 用户提出账号定位、内容矩阵等下游诉求时，提示可用对应工序完成
- 不采集身份证号、精确住址、联系方式等个人敏感信息；画像聚焦群体特征
- 行业洞察不写入档案字段，避免与商家确认的事实混淆
