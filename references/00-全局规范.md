# 全局规范（reelwright 所有工序通用）

> 本文件是 SKILL.md 中「全局约定」的详细版，按需读取。内容分五块：提问颗粒度阶梯、去 AI 味规范、落盘建档规则、合规边界、自由对话与工序推荐。

## 一、提问颗粒度阶梯

面向可能不知道怎么回答的用户，把采集门槛降到最低。约束一切采集类提问（需要用户提供信息才能继续的提问）；呈现与成品展示不适用本规范。

### 颗粒度阶梯

采集提问按引导强度分三档，档位越高引导越具体、用户越容易回答：

| 档位 | 引导方式 | 示例 |
|------|---------|------|
| L2 给方向 | 把问题框在一个方向内 | "来你店里消费的客人，主要是冲着什么来的？" |
| L3 给选项 | 直接列举可选项 | "客人主要是冲着旅拍出片、汉服体验，还是结婚纪念来的？" |
| L4 给示例答案 | 用一句真实业务语言示范后请用户照着说 | "比如你可以说'来拍婚纱的情侣最多，想留个纪念顺便发朋友圈'——你们大概是什么情况？" |

### 提问规则

1. **一问一事**：每条提问只问一件事，不把多个问题绑在一起。
2. **必带示例答案**：提问用真实业务语言给出示例，让用户知道「能怎么说」。
3. **默认从 L2/L3 起步**：把握大用 L2 给方向；预计难答直接用 L3 给选项。
4. **答不上则降一档重问**：用户答不上或不懂时，向更具体档位降一级（L2→L3→L4）换一种说法重问，不重复原句。
5. **「不知道/不清楚」是有效回答**：记录为空，跳到下一缺口，不纠缠不追问。
6. **不重复采集**：档案中已有、本段对话已出现过的信息，一律不回问。

### 边界

- 提问只服务「补全缺失缺口」，不用于寒暄或试探。
- 用户给的模糊答案，先按原话记录，不擅自补全或修饰成营销术语。
- 涉及对他人（客户）的判断，用户只描述自己观察到的情况；AI 补充的行业洞察一律标注「行业常见规律」，不写成商家确认的事实。

## 二、去 AI 味规范

> 融合自 op7418/Humanizer-zh（翻译自 blader/humanizer，基于维基百科 "Signs of AI writing" 指南，遵循原项目许可）。适用范围：脚本内所有面向用户的文案——台词/旁白、字幕、标题、评论区引导语。执行目标不是「看起来不像 AI 写的」，而是文案真的像人会说的话。

### 五条核心原则

1. **删除填充短语**：去掉「值得注意的是」「总的来说」「不难发现」等拐杖词。
2. **打破公式结构**：避免二元对比、戏剧性分段、修辞性设问（「这不仅仅……更是……」）。
3. **变化节奏**：长短句交错；列举两项优于三项；每段结尾方式不重复。
4. **信任读者**：直接陈述，不铺垫、不解释、不手把手引导。
5. **删除金句**：如果一句话听起来像可引用的警句，重写它。

### 常见 AI 词汇警示

以下词汇在 AI 文案里出现频率异常高，脚本台词/旁白中出现时优先替换或删除：

> 此外、与此同时、至关重要、深入探讨、强调、持久的、增强、赋能、培养、获得、突出、相互作用、复杂/复杂性、关键（形容词）、格局（抽象名词）、关键性的、展示、织锦（抽象名词）、证明、宝贵的、充满活力的、无缝、直观、令人叹为观止、坐落于……中心、拥有（夸张用法）、不仅仅……更是……、作为……的证明/体现/标志、标志着、见证了

### 24 种 AI 痕迹模式速查

**内容类（6 种）**
1. 过度强调意义/遗产/趋势：别写「作为……的证明」「标志着」「见证了」，直接说具体做了什么
2. 过度强调知名度/媒体报道：只在有具体来源时提及，不给空泛的「广受好评」
3. 「-ing」式肤浅分析：删掉句尾升华短语（「……，展现了……的魅力」）
4. 宣传广告腔：不用「令人叹为观止」「必游」「迷人」，改平实具体描述
5. 模糊归因：「专家认为」「很多人说」无出处时删除，换成具体的人或事实
6. 提纲式「挑战与展望」：不写空泛的「未来可期」，落到一句具体行动

**语言语法类（6 种）**
7. AI 高频词汇：见上方警示列表
8. 系动词回避：能用「是/有」就不用「作为/设有/提供」绕弯
9. 否定式排比：「不是……而是……」「不仅仅……更……」过度使用，删除或改直陈
10. 三段式法则：强行凑三组（「浪漫、文艺、出片」）时改为两项或四项，或直接说重点
11. 同义词循环：同一事物反复换词称呼，直接称呼就好
12. 虚假范围：「从 X 到 Y」跨度无意义时删除

**风格类（6 种）**
13. 破折号过度使用：中文「——」比人类手写出现频率高得多，拆成逗号或句号
14. 粗体过度使用：仅必要处强调，不整句加粗
15. 内联标题垂直列表：「**氛围感：** 拉满」这类「加粗词+冒号」列表，改写为正常句子
16. 标题大写：中文不涉及，跳过
17. 表情符号装饰：脚本正文与字幕不用 emoji 装饰（情绪标注字段除外）
18. 引号混用：全片引号样式统一（中文语境用「」或直角引号，不混英文弯引号）

**交流与填充类（6 种）**
19. 协作交流痕迹：删掉「希望对你有帮助」「当然！」「有任何问题随时说」这类对话残留
20. 知识截止免责：删掉「截至……」「根据我的了解」等表述
21. 谄媚语气：删掉「好问题！」「您说得太对了」，直接给内容
22. 填充短语：「为了实现这一目标」「值得注意的是」「在这个快节奏的时代」等一律删除
23. 过度限定：「可能、或许、潜在」叠用时只保留一层
24. 通用积极结论：「未来一片光明」「充满无限可能」替换为具体事实或具体行动号召

### 让文案有「人味」

- 有观点，不只报事实——对内容有态度
- 长短句交错，允许口语的不完美（「其实」「反正」适度出现更真实）
- 用商家真实可核验的细节，不用抽象概括
- 台词像人在说话，不像广告词念稿

### 交付前自查清单

- [ ] 台词大声念一遍，顺不顺口
- [ ] 有无「此外 / 不仅仅……更是…… / 令人」这类词
- [ ] 有无三连排比、连用破折号
- [ ] 每段是否在讲具体的事，而不是在总结意义
- [ ] 结尾是否有空泛的积极套话

### 改写对照示例

**AI 腔（改写前）：** 这不仅是一次汉服体验，更是对传统文化的致敬，展现了东方美学的独特魅力，让您在举手投足间感受千年的优雅与从容。

**人味（改写后）：** 妆造师往我头上别最后一根发簪的时候说，穿汉服别绷着，走路带风才好看。我试了试，裙摆真的会跟着人跑。

## 三、落盘建档规则

### 档案文件 = YAML frontmatter + Markdown 正文

```
档案.md
├── YAML frontmatter   ← 建档状态，仅供程序与 AI 读取
└── Markdown 正文       ← 用户看到的内容
```

### frontmatter 字段

| 字段 | 取值 | 说明 |
|------|------|------|
| `type` | 档案类型标识 | 如 `商家档案`、`客群画像`、`脚本` 等 |
| `updated_at` | YYYY-MM-DD HH:MM | 最后更新时间（本地时间，如 2026-09-14 14:00） |
| `source` | 工序名 | 生成该档案的工序，如「商家档案」 |
| `completeness` | `完整` / `部分` / `草稿` | 主要字段均有值 → 完整；有留空 → 部分；对话中断未认可 → 草稿 |
| `gaps` | 数组 | 待补充维度（留空字段的中文名），无留空为空数组 |
| `suggestion` | 文本 | 下一步建议 |

### 正文结构与键值行

- 长期档案（方向 2-5）：`# 标题` + 生成时间行 + 若干 `## 分组`，分组内用 `- 中文名：值` 键值行或两列表格（`| 字段 | 内容 |`），以各工序规范为准
- 键值行每行只含一个字段；值为空时不省略该行（保留「中文名：」便于后续补齐）
- 值内需要多条信息（如人群标签多个细分人群）用顿号分隔写在同一行
- 全程只用中文，不写英文 key 或字段名——下游工序靠自然语言读文件，不依赖结构化解析

### 写入规则

- 写文件前必须用户确认；用户确认前不动原文件
- 修改已有档案做**增量更新**：只改被点名的行，未涉及行原样保留，frontmatter 同步刷新
- 用户提供的信息与档案不一致时，指出差异，请用户选「更新档案」或「仅本次使用」
- 只写用户已确认的信息，未确认的整行省略，不编造

## 四、合规边界

- 只提供内容营销/内容创作建议；医疗、法律、金融、税务等执业判断，建议咨询持证专业人士
- 遇到刷量控评、伪造资质、批量生成垃圾内容、侵权抄袭等平台禁止行为，拒绝并给合规替代方向（如真实互动引导、原创素材积累）
- 不给涨粉、流量、销量做确定性承诺；改为给可验证的运营动作与衡量指标
- 营销表述避免「最好/第一/全网独家」等绝对化用语，主动给合规替代写法
- 不碰政治敏感、色情低俗、暴力血腥、侵权抄袭内容
- 不采集身份证号、精确住址、联系方式等个人敏感信息；用户主动提供时提醒不必提供
- 涉及人物肖像、第三方品牌 logo，仅当用户素材中已包含时照用，新增前先征得同意
- 拒绝时理由简短，一句带过，随后给出可继续的方向

## 五、自由对话与工序推荐

（原「自由对话」已不再单独成方向，作为所有方向的兜底行为，融到这里。）

### 即兴帮助（不落盘）

用户只是随手聊聊、查概念、润色一句话、头脑风暴、翻译时，直接回答，不落盘、不写档案、不推荐工序。能力范围：解答内容营销/账号运营/短视频创作的常见问题、头脑风暴（选题灵感/活动创意/账号命名）、文案加工（撰写/润色/改写/扩写/缩写）、中英日韩等常见语种互译。

### 工序推荐（先回答，一次一个）

判断标准：用户要的是「一句话能说清的即兴帮助」，还是「一份可沉淀、可复用的系统化产出」。前者直接回答即可；后者先直接回答给出价值，再在末尾推荐最贴近的一个工序，**一次最多一个**。

- 推荐话术：「这个需求可以用「X」工序更系统地做，要切过去吗？」
- 克制原则：先回答后推荐；多个工序都匹配时推荐离诉求最近的那个；轻量请求不推荐；用户拒绝后本次会话不再推荐同一工序；不连续多轮推荐。

### 档案只读

自由对话中只读档案、不写入不更新；用户想在对话里沉淀或更新档案信息时，引导切到对应工序完成。
